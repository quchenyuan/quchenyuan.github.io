中英混排的几个真问题

行高、字体回退顺序、以及为什么我没有给中文正文上 Web 字体。

2026年7月30日

给中英混排的博客做排版，麻烦不在审美，在几个具体的物理事实。

一、汉字是方的

拉丁字母有升部和降部，视觉重心靠上；汉字撑满字面框。同样的 line-height， 中文看起来会比英文挤。所以行高必须跟着语言走，而不是全站一个值：

:root { --measure: 68ch; }
html[lang^="zh"] { line-height: 1.75; --measure: 36em; }
html[lang="en"]  { line-height: 1.6; }

二、字体回退顺序会咬人

如果把中文字体写在拉丁字体前面，中文字体里那套半宽拉丁字母就会接管英文单词， 于是代码和英文术语会变得很难看。拉丁字体必须写在前面：

font-family: Newsreader, "PingFang SC", "HarmonyOS Sans SC", "Microsoft YaHei", sans-serif;

浏览器逐字符回退，所以拉丁字符命中第一个，汉字落到第二个。顺序错了，两边都难看。

三、我没上中文 Web 字体

一套完整的中文字体动辄几 MB——Noto Sans SC 全量接近 10 MB。 即便切片，首屏也要拉不少包。而系统字体在读者机器上已经存在，且质量不差。

顺带一句：霞鹜文楷很好看，但作者自己都说它「并不太适合大段正文排版」。

四、中西文之间的空格

中文与拉丁文之间加四分之一空格，观感会明显变好。这件事应该在构建期做，而不是让读者跑 JS：

构建期插入 → HTML 里就是对的 → 没有 JS，没有重排

如果哪天想给中文换一套定制字体，再用 cn-font-split 做切片就好，不必现在背这个包。
